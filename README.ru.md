# Claude love Gemini

Claude Code — оркестратор. Gemini CLI — исполнитель на массовой работе. Вы
формулируете задачу словами; Claude сам решает, что сделать самому, что
делегировать, проверяет фактический дифф и тесты и возвращает один отчёт.

Родственник [Claude love Codex](https://github.com/fafnirov/claude-love-codex):
тот же драйвер, те же гарантии, другой исполнитель. Смысл этого — **объём**:
механические рефакторинги, генерация тестов, рутинные миграции на движке со
щедрым бесплатным лимитом, чтобы дорогой исполнитель оставался для работы,
которая того стоит.

```bash
~/.claude/scripts/gemini-task.sh run --repo . --test "pytest -q" \
  --scope "tests/*" "напиши модульные тесты на все публичные функции src/parser.py"
```

## Что это даёт

- **Изоляция.** У каждой задачи свой `task_id`, своя ветка и свой git worktree.
  Рабочая копия не трогается.
- **Гейт качества по фактам.** Статус считается из кода возврата, фактического
  `git diff`, кода возврата тестов, разбора рисков и границ задачи — а не из
  слов исполнителя.
- **Атомарное слияние.** Результат собирается и проверяется во временном
  worktree; ref из `--into` двигается только после успешных тестов и только
  через compare-and-swap.
- **Работающие лимиты.** 3 попытки на задачу, бюджет времени, 2 одновременных
  исполнителя, тайм-ауты, защита от дублей и от «топтания на месте».
- **Никаких обходов подтверждений.** `-y`, `--yolo` и `--approval-mode=yolo`
  отклоняются до запуска движка. Правки автоподтверждаются только внутри
  worktree задачи, команды оболочки — нет.

## Требования

- [Claude Code](https://docs.anthropic.com/claude-code)
- [Gemini CLI](https://github.com/google-gemini/gemini-cli): `npm i -g @google/gemini-cli`
  с ключом `GEMINI_API_KEY`

> **Вход через Google-аккаунт может не сработать.** На Gemini CLI 0.65.0 OAuth
> проходит на стороне Google, а CLI его отклоняет: *«This client is no longer
> supported for Gemini Code Assist for individuals… migrate to the Antigravity
> suite of products»*. Antigravity — графическая среда без headless-режима, как
> исполнитель она не годится. Используйте ключ из
> [AI Studio](https://aistudio.google.com/) — там есть бесплатный уровень.

- git, Python 3 (`python3` или `python`), bash и GNU `timeout`
  (coreutils; на macOS: `brew install coreutils`)

## Установка

```bash
git clone https://github.com/fafnirov/claude-love-gemini.git
cd claude-love-gemini
bash install.sh
~/.claude/scripts/gemini-task.sh doctor
```

Установщик кладёт скрипты и скилл Claude Code в `~/.claude`, а правила для
исполнителя — в `~/.gemini/GEMINI.md` **только если этого файла ещё нет**.
`settings.json` и ваш `CLAUDE.md` он не трогает.

Оба проекта ставятся рядом: имена скриптов не конфликтуют.

## Как пользоваться в диалоге

Со скиллом ничего вызывать руками не нужно:

> напиши тесты на все публичные функции src/parser.py и прогони их

Решение о делегировании принимает Claude. Можно управлять явно: «используй
Gemini», «сделай сам», «запусти две задачи параллельно».

## Как устроен вызов движка

`gemini-run.sh` не полагается на знание флагов: он один раз читает
`gemini --help`, кеширует результат и подстраивается. Нужны две вещи — флаг
неинтерактивного запуска и `--approval-mode`. Режим `--read` отображается в
`default`, `--write` — в `auto_edit`. Если в установленной сборке управления
подтверждениями нет, обёртка **отказывается работать**, а не скатывается в
`--yolo`.

Gemini CLI не сообщает расход токенов, поэтому в отчётах стоит предупреждение
`token usage unavailable` вместо выдуманных цифр.

## Безопасность

Исполнитель работает с правами вашей учётной записи. Прочитайте
[docs/SECURITY.md](docs/SECURITY.md) прежде чем запускать это на машине с
боевыми ключами.

## Самопроверка

Наборы используют тестовый двойник вместо модели и ничего не стоят:

```bash
bash tests/run-tests.sh
bash tests/run-lifecycle.sh
bash tests/run-merge-atomic.sh
```

Что проверено, а что нет — в [docs/VERIFICATION.md](docs/VERIFICATION.md).
Главное: **связка с живым Gemini CLI ещё не проверялась**, драйвер унаследован
от проверенного проекта, а обёртка движка — нет.
